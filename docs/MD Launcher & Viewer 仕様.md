# MD Launcher & Viewer 仕様

散在するローカルの Markdown ファイルをブックマーク的に登録し、Chrome 上で整形表示する Chrome 拡張機能（Manifest V3）。

## 1. 前提条件

- 初回インストール時のみ、`chrome://extensions` の本拡張の詳細画面で **「ファイルの URL へのアクセスを許可する」** を ON にする（拡張機能ごとの設定で、ON にすると任意のローカルパスへのアクセスが永続化する）。
- 拡張機能の権限（manifest）：
  - `storage`：登録リストの保存
  - `tabs`：タブの URL 取得・検索・フォーカス・リロード
  - `sidePanel`：サイドパネル表示（Chrome 116 以上）
  - `host_permissions` / content script の `matches`：`file:///*.md`, `file:///*.markdown`
- 未許可の場合、拡張機能の UI に「ファイルURLへのアクセスが無効です」と案内を表示し、設定画面への手順を示す。
- ライブラリ（Markdown パーサ、ハイライタ等）は拡張にバンドルする（MV3 はリモートコード不可）。

## 2. 登録機能

### 2.1 登録方法

ブラウザのセキュリティ上、ドラッグ＆ドロップや File API ではファイルのフルパスを取得できない。そのため `file://` URL が確定できる以下の方法のみを採用する。

1. **今開いているタブを登録：** ローカルの `.md` / `.markdown` ファイルを Chrome にドラッグ＆ドロップして開いた状態で、拡張機能アイコンの「＋このファイルを登録」ボタンを押す（最も簡単）。対象外の URL のタブではボタンを無効化する。
2. **開いているタブを一括登録：** あちこちのフォルダから `.md` ファイルを Chrome に複数ドロップして開いた状態で、「現在のウィンドウの .md タブをすべて登録」ボタンを押す。
3. **パスの貼り付け登録：** サイドパネル（または管理画面）のテキスト欄に、パス（絶対パス）または `file://` URL を1行1件で貼り付けて追加する。
   - 絶対パスは `file://` URL に変換し、空白・日本語等は URL エンコードして保持する。
   - 拡張子が `.md` / `.markdown`（大文字小文字を区別しない）以外の行は無視し、結果（追加 n 件・重複 n 件・無効 n 件）を表示する。

### 2.2 表示場所

登録・リスト管理の UI は同一画面を次の3か所で提供する。ポップアップの「サイドパネル」ボタンでサイドパネルを開ける。サイドパネルは開いたままになるため、リスト項目を開いても閉じず、アクティブタブの切り替えに追従して「このファイルを登録」の有効／無効を更新する。

- ツールバーのポップアップ
- サイドパネル
- 設定ページ（タブ）

データは `chrome.storage.local` を共有し、いずれかで変更すると他方にも反映される。

### 2.3 リスト管理

- 同名ファイル（`README.md` 等）を区別できるよう、表示名（エイリアス）・タグ・メモを編集可能にする。表示名の初期値はファイル名。
- 重複判定は正規化後の `file://` URL の一致で行い、既存なら追加せず通知する。
- 一覧は検索（表示名・パス・タグ・メモ）とタグによる絞り込みに対応する。
- 項目の削除は一覧から行う（ファイル自体は削除されない）。
- **保存形式：** `chrome.storage.local` に軽量な JSON として保存する。

```json
{
  "id": "uuid",
  "url": "file:///Users/foo/docs/README.md",
  "name": "プロジェクトA README",
  "tags": ["projA"],
  "memo": "",
  "createdAt": "2026-11-16T00:00:00Z"
}
```

- 保存するのはメタ情報のみで、ファイルの内容は保存しない。

## 3. 閲覧・レンダリング機能

### 3.1 リストからの起動

- 登録リストの項目をクリックすると、該当の `file://` URL をタブで開く。
- 同一 URL（ハッシュ・クエリを除いて比較）のタブがすでにあれば、そのタブをフォーカスしてリロードする。なければ新規タブで開く。

### 3.2 レンダリング

- URL が `file:///*.md` または `file:///*.markdown` にマッチするページが開かれると、Content Script（`run_at: document_end`）が自動起動し、表示されている生テキストを Markdown レンダリングに差し替える。登録済みかどうかには依存しない。
- 対応範囲：GFM（表・タスクリスト・取り消し線・自動リンク）とコードブロックのシンタックスハイライト。
- **安全性：** レンダリング結果はサニタイズ（DOMPurify 等）してから DOM に挿入し、Markdown 内の生 HTML によるスクリプト実行を防ぐ。
- **相対パス：** 画像・リンクの相対パスは元ファイルの URL を基準に解決する。他の `.md` へのリンクは同様にレンダリングされる。
- 元のテキストに戻せるよう、「ソース表示」の切り替えを提供する。
- ページのリロード時は再レンダリングされるため、ファイル編集後の確認はリロードで行える。

### 3.3 例外・制約

- **ファイルが削除・移動されていた場合：** Chrome 標準の「ファイルが見つかりません」画面が表示される（拡張側では検知しない。不要な項目は一覧から削除する）。
- **Chrome が `.md` をダウンロード扱いにする場合：** 環境によっては `file://` の `.md` がテキスト表示されずダウンロードされることがある。その場合 Content Script は動作しないため、拡張機能内のビューアページ（`viewer.html?src=<file:// URL>`）で `fetch` して同じレンダリングを行うフォールバックを用意し、リストからの起動はこちらを使う。実装時に対象環境で挙動を検証し、必要な場合にフォールバックを既定とする。
- ファイル URL へのアクセス許可が OFF の場合は §1 の案内を表示する。
